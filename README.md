# Typer

**Markdownの気軽さで文章を書き、必要な書式だけを指定して、読みやすいPDF報告書を簡単に作成できる軽量デスクトップアプリケーション**

Microsoft Wordのような高機能ワープロの完全な代替ではなく、**テキストを中心とした簡潔な操作で、体裁の整った社内報告書・業務文書・議事録・手順書を効率よく作成すること**を目指しています。

---

## 主な特徴

- **Markdownベースの書き味＋業務文書向け拡張構文**
  - 基本は標準Markdown（見出し・段落・リスト・表・引用・コード）のまま記述可能
  - 標準Markdownでは手が届かない **「表の列幅指定」「段落の行間・右寄せ/中央寄せ」「部分的な文字色・文字サイズ変更」「任意改ページ」「A4用紙・余白設定」** をシンプルな構文で制御可能
- **Typst組版エンジン内蔵による高品質な日本語PDF出力**
  - 外部ツールのインストール不要（RustクレートとしてTypstを直接内蔵）
  - 日本語の文字折り返し・禁則処理、見出し直後の不自然な改ページ抑制（`sticky`）、表ヘッダデザイン・セル内折り返しに対応
- **軽快な2ペインUI（`egui` 採用）と非同期リアルタイムプレビュー**
  - 左ペイン：独自拡張構文のシンタックスハイライト＆ワンクリック書式挿入バー付きエディタ
  - 右ペイン：A4用紙のリアルタイムページプレビュー（拡大・縮小・複数ページスクロール対応）
  - 組版処理をバックグラウンドスレッドに分離＋デバウンス処理により、高速タイピング中も入力が一切引っかからない設計
- **PDF出力 ＆ 単一HTML出力の両対応**
  - 提出・印刷用の **PDF出力** と、ページ境界に依存せずブラウザで連続閲覧できる **単一HTML出力（CSS内包）** の両方に対応
- **単一実行ファイル（ポータブル `.exe`）指向**
  - 外部ランタイムや別プロセス呼び出しを行わず、Windows標準の日本語フォント（BIZ UDゴシック/明朝、游ゴシック/明朝、メイリオ等）を活用してスタンドアロン動作

## 独自拡張マークアップ記法

### 1. 文書全体設定（先頭フロントマター）
```yaml
---
paper: A4
orientation: portrait   # portrait (縦) / landscape (横)
margin: 20mm
font-size: 10.5pt
line-height: 1.5
font: gothic            # gothic (ゴシック) / mincho (明朝)
---
```

### 2. 表の列幅指定
標準Markdownの表の直前に `{widths: ...}` を1行添えるだけで、列幅比率や固定幅を指定できます。
```markdown
{widths: 22%, 48%, 30%}
| 項目 | 内容・対応状況 | 備考・担当 |
| :--- | :--- | :--- |
| **発生日時** | 2026年10月14日 10:15 〜 10:48 | 監視アラートにて検知 |
| **直接原因** | バックアップジョブの重複によるディスクI/O飽和 | [設定ミス]{red}による重複 |
```

### 3. 段落・見出しの配置と行間制御
```markdown
{align: right}
2026年10月16日  
情報システム部 業務改善推進チーム

{align: center, size: 16pt}
**社内システム障害対応および再発防止策報告書**

{line-height: 1.2, size: 9.5pt}
※この段落だけ行間と文字サイズを少しコンパクトに詰めて表示します。
```

### 4. インライン文字装飾（文字色・文字サイズ）
表のセル内でもパイプ `|` と衝突しない `[テキスト]{属性}` 記法と、従来型の `{color:red|テキスト}` 記法の両方に対応しています。
- `[重要事項]{red}` / `[補足]{blue}` / `[正常]{green}`
- `[カスタム装飾]{color: red, size: 12pt}`
- `{color:red|重要事項}`

### 5. 任意改ページ
```markdown
:::pagebreak
```

## アーキテクチャ・ディレクトリ構成

将来的なUIフレームワークの比較検証（`egui` ⇄ `Slint`）や独自構文の拡張が容易に行えるよう、4層の疎結合なモジュール構成をとっています。

```text
Typer/
├── Cargo.toml
├── docs/
│   ├── requirements.md   # 要件定義書 (v0.2)
│   └── roadmap.md        # 開発ロードマップ・マイルストーン
└── src/
    ├── main.rs           # エントリポイント
    ├── model.rs          # 内部文書モデル (AST / 拡張属性の器を持つ中間表現)
    ├── parser.rs         # 標準Markdown + 独自拡張構文パーサー
    ├── typst_gen.rs      # 内部文書モデル ➔ Typstコード変換器
    ├── typst_engine.rs   # インメモリTypst組版・プレビュー描画・PDF出力エンジン
    ├── html_export.rs    # 内部文書モデル ➔ 単一HTML+CSS出力器
    ├── ui.rs             # egui 2ペインデスクトップUI・非同期ワーカー・構文ハイライト
    └── sample.rs         # 起動時サンプル業務報告書原稿
```

## ビルドと実行方法

### 必要環境
- Windows 10 / 11
- Rust ツールチェーン (`rustup` / `cargo`)

### 開発実行・テスト
```powershell
# 単体・結合テストの実行
cargo test

# デスクトップアプリの起動
cargo run
```

### リリースビルド（配布用単一 `.exe` の生成）
```powershell
cargo build --release
```
生成された `target\release\typer.exe` を単体で配布・実行できます。
