# 軽量マークアップ文書作成アプリ 開発ロードマップ

**対象要件定義：** v0.2  
**基本方針：** 「まず標準Markdownで一気通貫に動く単一EXEアプリ（器つき）を作り、実際に触りながら独自拡張構文を設計・追加する」

---

## 全体アーキテクチャ構想

将来的にUIフレームワークの比較（`egui` ⇄ `Slint`）や独自構文の調整がいつでもできるよう、最初から1つのバイナリ内で**4つのモジュール（層）**を明確に分けて作成します。

```
[ 1. UI層 (egui / eframe) ]
   ├── 左ペイン：テキストエディタ（日本語IME対応、後の構文ハイライト）
   ├── 右ペイン：ページプレビュー表示（画像テクスチャ描画、ズーム・スクロール）
   └── ツールバー：ファイル開く/保存、PDF出力、HTML出力
          │ (Markdown文字列を渡す)
          ▼
[ 2. パーサー層 (parser) ]
   ├── Step 1では `pulldown-cmark` で標準Markdownを解析
   └── Step 2で独自属性（`{widths: ...}` 等）の解析を追加
          │
          ▼
[ 3. 内部文書モデル層 (model / AST) ]  ★ここが要（かなめ）
   ├── Document (ページ設定: 用紙サイズ、余白、基本フォントサイズ、基本行間)
   ├── Block要素 (見出し、段落、リスト、表、改ページ 等)
   │     └── 各Blockに「拡張属性用の空き箱（Option型）」を最初から持たせる
   └── Inline要素 (テキスト、太字、斜体、装飾付きスパン 等)
          │
          ├──────────────────────────┐
          ▼                          ▼
[ 4a. Typst組版・出力層 ]     [ 4b. HTML出力層 (Step 3〜) ]
   ├── AST ➔ Typstコード変換         └── AST ➔ 単一HTML+CSS生成
   ├── インメモリ組版 (typst)
   ├── プレビュー画像生成 (typst-render)
   └── PDFバイナリ生成 (typst-pdf)
```

### Milestone 1：基本Markdownの描画プロトタイプ（垂直スライス）
**目的：** 独自構文はまだ入れず、**「普通のMarkdownを書いたら、リアルタイムで綺麗なA4ページプレビューが出て、PDF保存できる単一EXE」** を完成させる。

- [ ] **1-1. 拡張用の「器」を備えた内部文書モデル（AST）の定義**
  - 標準Markdownの要素（見出し、段落、箇条書き、番号付きリスト、表、引用、コード、水平線）を表現する構造体を作成する。
  - 表には `column_widths: Option<Vec<ColumnWidth>>`、段落には `line_height: Option<f32>` や `align: Option<Alignment>`、インラインには `color: Option<Color>` などのフィールドを最初から用意しておく（初期値はすべて `None`）。
- [ ] **1-2. 標準Markdownパーサーの実装**
  - `pulldown-cmark` を使い、GFMテーブルを含む標準Markdownを内部文書モデル（AST）に変換する。
- [ ] **1-3. 内部文書モデル ➔ Typst変換器の実装**
  - ASTからTypstマークアップ（またはTypst要素）を生成する処理を実装する。
  - 日本語報告書向けに、デフォルトで綺麗に見えるA4余白、フォント（明朝/ゴシック）、見出しスタイル、表の罫線スタイルを設定する。
- [ ] **1-4. 2ペイン画面（エディタ＋ページプレビュー）とPDF出力の結合**
  - 左ペインでテキストを編集すると、右ペインにA4用紙のプレビュー（複数ページ対応・影付き）が表示される画面を作る。
  - 「PDF出力」ボタンから任意の場所に `.pdf` ファイルを書き出せるようにする。

> **★完了条件（ゴール）：**  
> サンプルの業務報告書（標準Markdownで書かれた見出し・文章・箇条書き・表）をアプリに貼り付け、プレビューを見ながら編集し、綺麗な日本語PDFとして出力できること。

### Milestone 2：独自拡張構文の設計と実装（表・行間・文字色・ページ設定）
**目的：** Milestone 1のアプリで実際に業務文書を書きながら、「ここを調整したい」という箇所に対して最も自然な拡張構文を決め、内部文書モデルの「空き箱」に値を流し込む。

- [ ] **2-1. 拡張構文の仕様確定（サンプル文書による机上＆実機テスト）**
  - 表の中で使っても破綻せず、タイプしやすい記号体系を確定する。
- [ ] **2-2. 文書全体設定（フロントマター）の実装**
  - 文書先頭の `---` 〜 `---` で、用紙サイズ（A4縦/横）、余白（`margin`）、基本文字サイズ（`font-size`）、基本行間（`line-height`）を変更できるようにする。
- [ ] **2-3. 表の列幅・配置制御の実装（最重要）**
  - `{widths: 20%, 50%, 30%}` や `{widths: 30mm, auto, 40mm}` などの指定を解析し、Typstの `#table(columns: (...))` に反映させる。
- [ ] **2-4. 段落属性（部分的な行間・右寄せ/中央寄せ）の実装**
  - 日付や署名欄の右寄せ（`{align: right}`）、特定段落の行間調整（`{line-height: 1.2}`）、段落前後の余白調整を反映させる。
- [ ] **2-5. インライン文字装飾（文字色・部分文字サイズ）の実装**
  - `[重要]{red}` などの記法を解析し、Typstの `#text(fill: red)[...]` に反映させる。
- [ ] **2-6. 改ページ制御の実装**
  - 任意改ページ（`:::pagebreak` 等）と、見出し直後の改ページ抑制・表の分割制御を確認・調整する。

> **★完了条件（ゴール）：**  
> 標準Markdownでは不可能だった「列幅を揃えた見やすい表」「右寄せの日付・宛名」「赤字の強調」「狙った位置での改ページ」を含む業務報告書PDFが作成できること。

## Milestone 13：Markdownの構造を正しく扱う（リスト・引用・脚注）
**目的：** ふだんの書き方で文章が消えたり位置がずれたりしないようにし、報告書でよく使う記法（チェックリスト・脚注）を3形式（PDF・HTML・Word）すべてで使えるようにする。

**方針：** パーサーのブロック管理を「引用・リスト・リスト項目・段組み・脚注定義」を積み重ねる1本のスタックに作り直し、入れ子の組み合わせを個別対応ではなく構造的に扱う。リスト項目は「本文＋任意の子ブロック（段落・コード・引用・入れ子リスト等）」を持てるようにする。

- [x] **13-1. 空行を挟んだリスト（ルーズリスト）** — 項目の段落がリストの外へ出て、空の「・」が並ぶ不具合を修正
- [x] **13-2. リスト項目内のブロック** — 項目の下に書いたコードブロック・続きの段落・引用・見出しを、その項目の子として正しい位置に出す
- [x] **13-3. 引用の入れ子** — `> > 内` で外側の文章が消え、空の引用枠が増える不具合を修正
- [x] **13-4. 段組み内の引用** — `:::columns` 内の引用で枠だけが段組みの外に出る不具合を修正。閉じ忘れの `:::columns` は文書末で自動的に閉じる（従来は中身ごと消えていた）
- [x] **13-5. 1以外から始まる番号付きリストの入れ子（Typst）** — リストをTypstの関数形式（`#list` / `#enum`）で出力し、どの開始番号・入れ子・子ブロックでも崩れないようにする
- [x] **13-6. チェックリスト** `- [ ]` / `- [x]` — PDFは枠と✓を図形で描画（フォントに依存しない）、HTMLは無効化したチェックボックス、Wordは ☐ / ☑
- [x] **13-7. 脚注** `本文[^1]` ＋ `[^1]: 注記` — PDFはTypstの `#footnote`（ページ下部）、HTMLは文末の注記一覧と相互リンク、WordはWord本来の脚注（`footnotes.xml`）。定義のない参照は `[^1]` のまま文字として残す
- [x] **13-8. HTMLタグの扱いを明文化** — `<br>` 以外のHTMLタグは出力しない（コメント `<!-- -->` もメモ書きとして使える）ことをマニュアルに記載
- [x] **13-9. リスト項目内の改行** — 項目の途中で改行した行が前の行と空白なしでくっつく不具合を修正（段落と同じ扱いにする）
- [x] **13-10. Wordの本物のリスト** — 「•」「1.」を文字で書くのをやめ、Wordの箇条書き・段落番号（`numbering.xml`）を使う。番号の振り直し・Tabでのレベル変更がWord上でできるようになる。あわせて、Word出力で引用内の通常段落にインデントが付いていなかった問題も直す
