### 1.2 現状の評価（改訂時点。Phase 1〜4 の結果は第6章）

- **表現力は業務文書には十分な水準に達した。** 書式を増やすより、今ある機能の信頼性と使い勝手を上げる段階にある。
- **一番の弱点は「間違えたときに原稿のどこが悪いか分からないこと」。** 組版エラーの行番号は生成したTypstコードの行で、原稿の行と対応しない。`{color: ...}` などの書き間違いは警告なしに無視される。
- **Word出力はMicrosoft Word実機で未確認。** 社内では「Wordで出して」と言われる場面が多く、崩れると信頼を失いやすい。
- **業務文書で目立つ機能の穴は表のセル結合。** 稟議書の承認欄や比較表で必要になる。
- **保守面では `ui.rs`（約3,000行）が大きく、出力の回帰を確かめる仕組みがない。** 機能を足すほど効いてくる。

## 2. 優先順位の考え方

1. **毎日の書き心地に効くものを先に。** 「書いてすぐ見る」がこのアプリの価値なので、エラーの分かりやすさを最優先にする。
2. **新機能より、出力の信頼性。** 3形式対応を看板にしている以上、Wordで崩れないことを確かめてから機能を足す。
3. **要件定義の原則を守る。** 単一EXE・軽さ・Markdownの書き味を損なう機能は入れない（第5章）。
4. **需要が確認できないものは保留。** 実際の文書作成で必要になったときに着手する（第4章）。

規模の目安：**S** = 半日〜1日、**M** = 数日、**L** = 1週間以上

## 3. 今後のフェーズ

### Phase 1：間違いにすぐ気づける（最優先）

**目的：** 書き間違いや組版エラーが起きたとき、原稿のどの行を直せばよいかがすぐ分かるようにする。

- [x] **14-1. 原稿の行と生成コードの行の対応表（M）**
  - パーサーは既に `into_offset_iter` で各要素の原稿上の位置を受け取っているので、これを `Block` に持たせる。
  - `typst_gen` がTypstコードを出すときに「生成コードの何行目が原稿の何行目由来か」の対応表を一緒に返す。
  - 以降の14-2〜14-4はすべてこの対応表を使う。
- [x] **14-2. 組版エラーを原稿の行番号で表示（S）** — 現在の `[生成コード N行目]` を `[原稿 N行目]` に置き換える（対応できない場合だけ従来の表記）。
- [x] **7-1. 属性記法の誤記を表示（M）** — `{colr: red}` のような未知のキー、`{size: 12}` のような単位抜け、閉じ忘れの `{` を検出し、プレビュー上部に「原稿 N行目: 〜」の形で出す。組版自体は止めない。
- [x] **14-3. エラー行へのジャンプ（S）** — エラー表示をクリックするとエディタの該当行へ移動する。
- [ ] **14-4.（任意）カーソル位置にプレビューを追従（M）** — 今は見出し一覧からのジャンプだけ。対応表を使い、エディタのカーソルがある段落付近へプレビューを寄せる。ON/OFFを切り替え可能にする。

> **完了条件：** 生Typstコードの誤りや属性の書き間違いを含む原稿で、エラー表示から1クリックで原稿の該当行に移動できること。

### Phase 2：Wordで崩れない

**目的：** Word出力を「念のため確認が必要な機能」から「安心して渡せる機能」にする。

- [ ] **6-4 / 13-14. Microsoft Word実機での確認（S・要実機）**
  - 全機能を使った確認用の原稿を `docs/` 以下に置き、見るべき点をチェックリストにする（警告ダイアログが出ないか、フォント、表、画像、目次のフィールド更新、数式の高さ、箇条書き・段落番号、脚注）。
  - 実機での確認作業は手元にWordがある環境で行う。見つかった崩れはこのフェーズ内で直す。
- [x] **6-2. リンクをクリックできるようにする（S）** — `w:hyperlink` とリレーションを出力する。
- [x] **14-5. 文字背景色 `{bg: ...}` を反映（S）** — 文字には `w:shd`、セル全体の塗りつぶしにはセルの `w:shd` を使う。

> **完了条件：** 確認用の原稿をWordで開いて警告が出ず、チェックリストの全項目がPDFと同等に見えること。

### Phase 3：表の弱点を埋める

**目的：** 業務文書で一番よく使う「表」で、Excelから移ってきた人が困らないようにする。

- [x] **15-1. セル結合の記法を決める（S・要判断）**
  - 案：セルに `<` だけを書くと左のセルと結合、`^` だけを書くと上のセルと結合。文字としての `<` `^` は `\<` `\^` と書く。
  - 普通のMarkdownビューアで見ても表が崩れず、`|` とも衝突しない。実際の稟議書・比較表を書いて使い勝手を確かめてから確定する。
- [x] **15-2. セル結合の3形式対応（M）** — Typstは `table.cell(colspan:, rowspan:)`、HTMLは `colspan` / `rowspan`、Wordは `w:gridSpan` / `w:vMerge`。列幅指定・ヘッダー背景との組み合わせもテストする。
- [x] **15-3. Excelからの貼り付けで表を作る（M）** — クリップボードの内容がタブ区切りの複数行なら、Markdownの表に変換して貼る。通常の貼り付けを邪魔しないよう、専用のショートカット（例：`Ctrl+Shift+V`）かボタンにする。

> **完了条件：** 承認欄（押印欄）付きの稟議書を、Excelから表を貼り付けて結合を指定するだけで、3形式とも崩れずに出力できること。

### Phase 4：繰り返し作業を減らす

- [x] **8-1. 現在の文書をテンプレートとして保存（S）** — `%APPDATA%\Typer\templates\` に `.md` として保存し、「📋 テンプレート」メニューに内蔵の4種類と並べて出す。
- [x] **8-2. テンプレート管理（S）** — 名前の変更・削除・フォルダを開く。
- [x] **16-1. 用紙サイズの追加（S）** — ページ設定バーにA3・B5・Letterを追加（Typstは対応済みなので、主にGUIと検証）。
- [x] **16-2. 自動保存を全タブに（S）** — 現在は表示中のタブだけが対象。

### 並行して進める：足回り

機能追加の合間に少しずつ進める。Phase 1〜3の変更が大きくなる前に着手するほど効果がある。

- [ ] **5-1b. `ui.rs` の第二段の分割（M）** — エディタ、プレビュー、ツールバー、ファイル操作をそれぞれ別モジュールへ。
- [ ] **5-2. 出力の回帰テスト（M）** — 確認用の原稿から作るTypstコード・HTML・Word内部のXMLを保存しておき、変更前後で差分を確かめる。PDFの画像比較は後回しにする。
- [ ] **17-1.（任意）リリースの整備（S）** — タグを打つとCIがリリース版の `typer.exe` を作って添付する。バージョン番号（現在0.1.0）の付け方を決める。

## 5. やらないこと

要件定義の原則（単一EXE・軽さ・Markdownの書き味）とぶつかり、規模にも見合わないため、当面は扱わない。

- **WYSIWYG編集**（プレビュー上で直接書式を編集する方式）
- **Word・その他形式の読み込み**（Word出力は一方向のまま）
- **クラウド共同編集・リアルタイム複数人編集**
- **マクロ・スクリプト実行、データベース連携**

## 6. Phase 1〜4 の実装メモ（2026年11月25日）

計画にはなかったが、作業中に見つけて直したもの・足したもの：

- **フロントマターの行末コメント・引用符**：マニュアルの例（`font: gothic   # 説明`、`accent-color: "#1a73e8"`）をそのまま写すと、コメントや引用符まで値として読まれ、フォント指定が壊れていた。
- **Word出力の段落の寄せ・文字色・文字サイズ**：`{align}` `{color}` `{size}` が段落・見出しで無視されていた（READMEは「全形式に反映」と記載）。
- **Word出力の表の列幅**：`{widths: ...}` が反映されず全列等幅だった。
- **Word出力のヘッダー・フッター・ページ番号**：出力されていなかった。PDFと同じ配置で出すようにした（透かしは未対応のまま）。
- **Word出力のスキーマ順序**：`w:rPr` `w:pPr` `w:tblPr` `w:sectPr` の子要素の順序と `w:pgMar` の必須属性を直した。Wordが「修復」を求める原因になりうる箇所。
- **CIの書式チェック**：mainで `cargo fmt --check` が失敗し続けていたため、整形だけのコミットで直した。
