# Typer 実践ガイド ― 実例で覚える業務文書の作り方

対象：Typer 0.1.0 / Windows。実装確認日：2026年10月18日。

Typerで文書を作り、保存し、提出するところまでを一冊でたどる実用マニュアルです。初めて使う方は第1章から、書き方を調べたい方は第4～7章、すぐ原稿が必要な方は第8章から利用してください。ショートカットの全一覧は第10章にあります。

本書の業務名・人名・金額・事象は説明用の架空例です。完成原稿はコード枠の中身だけをコピーして、新規タブへ貼り付けて使えます。既存文書を置き換えずに試すには、先に `Ctrl+T` を押してください。

## 第1章 最初の一枚を作る

### 1.1 起動からPDF出力まで

1. `typer.exe` を起動します。最近使ったファイルの先頭を読み込めればその文書が開き、読み込めなければサンプル報告書が表示されます。
2. `Ctrl+T` で新規タブを作ります。
3. エディタに初期設定が入っていたら、エディタ内をクリックして `Ctrl+A` で全選択し、次の原稿に置き換えます。
4. 右側のプレビューで、見出し・表・色文字を確認します。
5. `Ctrl+S` で `週次報告.md` として保存します。
6. `Ctrl+P` で `週次報告.pdf` を出力します。
7. 下部に現れる「開く」ボタンでPDFを確認します。

```markdown
# 業務改善 週次報告

## 今週の結論

申請書の入力項目を整理し、確認時間を**1件あたり5分から3分へ短縮**しました。
試行結果は[順調]{green}です。

{widths: 25%, 50%, 25%}
| 項目 | 実施内容 | 状態 |
| :--- | :--- | :---: |
| 入力項目 | 重複していた2項目を統合 | 完了 |
| 手順書 | 新しい入力例を追加 | 確認中 |

## 次週の予定

- 担当者3名で手順書を確認する
- 修正後の書式を共有する
```

確認できる仕上がり：タイトルと小見出しに階層がつき、短縮時間が太字、「順調」が緑色になります。表の中央列は左右の列より広くなります。

### 1.2 最初に覚える五つの操作

| やりたいこと | 操作 |
| :--- | :--- |
| 別の文書も並行して書く | `Ctrl+T` |
| 編集できる原稿を残す | `Ctrl+S` |
| 直前の変更を戻す | `Ctrl+Z` |
| 相手に提出するPDFを作る | `Ctrl+P` |
| 章の位置を探す | `Ctrl+Shift+O` でアウトラインを開く |

**原稿の保存と出力は別操作です。** PDFを出力しても `.md` 原稿の保存にはなりません。提出前には `Ctrl+S` と出力の両方を行います。`Ctrl+P` はPDFファイルの出力であり、プリンターへの直接印刷ではありません。紙に印刷する場合は、出力したPDFを開いて印刷します。

## 第2章 画面と文書の管理

### 2.1 画面の読み方

| 場所 | 役割・操作 |
| :--- | :--- |
| 上部ツールバー | 新規、開く、最近使ったファイル、保存、別名保存、Undo/Redo、検索・置換、各形式の出力 |
| ページ設定バー | 用紙の向き、フォント、余白、文字サイズ、行間、配色、ページ番号。`Ctrl+,` で開閉 |
| 左端のアウトライン | 見出しの一覧。クリックして原稿の該当位置へ移動 |
| タブバー | 文書の切り替え、＋で新規タブ、×で閉じる |
| 左のエディタ | 記号を含む原稿を書く。書式挿入バーから構文を挿入可能 |
| 右のプレビュー | PDF向けの組版結果をページ単位で確認。直接文字を編集する場所ではない |
| Typstコードパネル | 生成された組版用コードを表示。「コピー」で取得可能 |
| 下部ステータスバー | ファイル名、未保存の印、カーソル位置、文字数・行数、ページ数、組版時間、保存・出力通知 |

プレビューは入力後に自動更新されます。表示倍率は50～250%で、＋／－ボタンとキー操作は15ポイントずつ変化します。倍率を変えても、原稿の文字サイズやPDFの用紙寸法は変わりません。

「ライト／ダーク」または `Ctrl+Alt+D` で画面のテーマを切り替えます。この設定は次回起動にも引き継がれます。PDFの紙面配色を変えたい場合は、テーマではなく文書の配色や文字色を指定します。

### 2.2 「新規」と「新規タブ」の違い

| 操作 | 現在のタブへの影響 |
| :--- | :--- |
| 新規 / `Ctrl+N` | 現在のタブを新規文書に置き換える |
| ＋ / `Ctrl+T` | 現在の文書を保持し、新しいタブを追加 |
| 開く / `Ctrl+O` | 選んだファイルで現在のタブを置き換える |
| 最近使ったファイル | 選んだファイルで現在のタブを置き換える |
| `.md` / `.txt` のドロップ | 新しいタブとして読み込む |
| × / `Ctrl+W` | 現在のタブを閉じる。最後の1枚では空の新規文書に戻る |

置き換えやタブを閉じる操作で編集中の変更がある場合、保存確認が表示されます。「保存せずに続行」は変更を捨てる操作です。別の報告書を参照しながら書く場合は、`Ctrl+T` の後に `Ctrl+O` を使うと分かりやすく操作できます。

タブごとに原稿、保存先、Undo/Redo履歴、カーソル位置が保持されます。起動時に全タブを復元する機能はなく、前回の未保存タブがそのまま戻るものではありません。

### 2.3 内蔵テンプレートを使う

書式挿入バーの「テンプレート」から、議事録、障害・インシデント報告書、稟議書、日報を挿入できます。新規文書を作る機能ではなく、**現在のカーソル位置にひな形を挿入する機能**です。選択範囲がある場合は置き換わるため、文書全体のひな形として使うなら新規タブで実行します。

挿入後は、日付、担当者、金額、「入力してください」などを自分の内容へ変更します。挿入される日付は固定のサンプル値で、当日の日付へ自動更新されません。右寄せ段落の挿入ボタンに含まれる日付も同様です。

## 第3章 用紙と文書全体の設定

### 3.1 GUIで設定する

`Ctrl+,` でページ設定バーを開きます。設定変更は原稿先頭の設定にも反映され、`Ctrl+Z` で戻せます。

| 設定 | GUIの選択肢 | 使いどころ |
| :--- | :--- | :--- |
| 用紙 | A4縦 / A4横 | 通常の報告書は縦、横に長い比較表は横 |
| フォント | ゴシック / 明朝 | 操作手順はゴシック、文章主体の文書は明朝も選択可能 |
| 余白 | 15 / 20 / 25mm | 通常は20mm、書き込み余地が必要なら25mm |
| 文字 | 9.5 / 10 / 10.5 / 11 / 12pt | まず10.5ptで作り、読みやすさを見て調整 |
| 行間 | 1.1～2.2、0.1刻み | 長文では1.5を起点に調整 |
| 配色 | 青 / 緑 / 赤 / 紫 / 橙 | 見出しの罫線やリンク等のアクセント |
| ページ番号 | チェックで表示・非表示 | PDFの「現在ページ / 総ページ数」を切り替える |

設定を省略した文書は、A4縦、余白20mm、10.5pt、行間1.5、ゴシック、青系アクセント、ページ番号ありとして扱われます。フォントの実際の見た目はPCにある日本語フォントにも依存します。

### 3.2 原稿から設定する

次の部分を、文書の**先頭**に一度だけ置きます。上下の `---` も必要です。

```yaml
---
paper: A4
orientation: portrait
margin: 20mm
font-size: 10.5pt
line-height: 1.5
font: gothic
accent-color: #1a73e8
header: 業務改善プロジェクト
footer: 社内限定
page-number: on
---
```

| キー | 意味・指定例 |
| :--- | :--- |
| `paper` | 通常は `A4` を使う |
| `orientation` | `portrait`＝縦、`landscape`＝横。「横」「横向き」も認識 |
| `margin` | 四辺共通の余白。例：`20mm` |
| `font-size` | 基本文字サイズ。例：`10.5pt` |
| `line-height` | 基本行間の調整値。手入力は0.8～4.0に制限される |
| `font` | `gothic`＝ゴシック、`mincho`＝明朝 |
| `accent-color` | `#1a73e8` のような色。見出し・リンクなどの配色に使用 |
| `header` | PDFの各ページ上部に入れる文字。不要なら行ごと削除 |
| `footer` | PDFの各ページ下部に入れる文字。ページ番号が有効なら併記 |
| `page-number` | `off` / `false` / `no` / `none` / `0` で非表示。それ以外は表示 |

**設定欄は完全なYAML処理ではなく、Typer独自の簡易解析です。** 本書の例のように、値に引用符や行末コメントを付けずに記述してください。たとえば `line-height: 1.5 # 行間` は数値として解析されません。説明コメントが必要なら `# 説明` を独立した行に置きます。ヘッダーとフッターはこの欄で直接指定し、GUIからは入力しません。

PDFではヘッダー・フッターを各ページに繰り返します。HTMLでは文書の先頭・末尾に一度表示します。Wordでの対応範囲は第9章を参照してください。

### 3.3 全体設定と部分指定を使い分ける

全体を11ptにするなら `font-size: 11pt`、注記の段落だけ小さくするなら次のように書きます。

```markdown
{line-height: 1.2, size: 9.5pt}
※集計対象は10月分の受付データです。取消済みの申請は含みません。
```

属性行は直後のブロックに適用されます。以降の文書全体を変更する指定ではありません。

## 第4章 本文を書く

### 4.1 見出し・段落・リスト

```markdown
# 文書タイトル

## 1. 結論

ここに結論を書きます。空行を入れると次の段落になります。

ここからは別の段落です。

### 1.1 判断の根拠

- 作業時間が短くなった
- 確認漏れが減った

1. 原稿を保存する
2. PDFを出力する
3. 出力結果を確認する
```

`#` の後には半角空白を入れます。見出しは `#` から `######` までの6段階です。単に文字を大きくした段落はアウトラインや目次には入りません。章として扱いたい箇所には見出し記号を使います。

番号付きリストは `5. 手順` のように途中の番号から開始できます。入れ子リストや複数段落を含む複雑なリストは、この実装では階層を十分に保持できないため、単純な一段のリストを使ってください。脚注・タスクリスト・通常本文の数式を自動変換する機能はありません。

### 4.2 改行と段落を区別する

原稿でEnterを1回押しただけの改行は、仕上がりで強制改行されるとは限りません。段落を分けるなら空行、段落内で改行するなら行末の半角バックスラッシュを使います。

```markdown
情報システム部\
業務改善チーム\
担当：山田
```

`Shift+Enter` で挿入される `<br>` も段落内の改行に使えます。表の中では、行そのものを分けずに `<br>` を使います。縦方向の余白を増やすときは空行を重ねるのではなく `:::space 1em` を使います。

### 4.3 太字・斜体・下線・色・ハイライト

```markdown
**提出期限は10月23日です。**
*補足説明です。*
[承認が必要です]{underline}
~~旧手順は廃止しました~~
[要対応]{red} [確認中]{orange} [完了]{green}
[参考情報]{blue} [検討事項]{purple}
[補足]{gray} [本文色]{black}
[金額は税込です]{bg: #fff2cc}
[最優先]{color: #c5221f, size: 12pt, underline}
```

文字を選択して `Ctrl+B` / `Ctrl+I` / `Ctrl+U`、または色ボタンを押すと、その範囲を記号で囲みます。未選択なら例文を挿入し、その例文部分が選択されます。もう一度押して装飾を解除するトグル操作ではありません。解除するときは囲み記号を削除するか、直後ならUndoします。

任意の色はHEX入力欄に `#188038` などを入れ、「適用」を押します。3桁の `#rgb` と6桁の `#rrggbb` を入力できます。状態は色だけに頼らず、「要対応」「完了」のような文字でも示すと白黒印刷時も判別できます。

### 4.4 配置・幅・文字色を段落単位で変える

```markdown
{align: right}
2026年10月18日\
情報システム部 山田

{align: center, size: 16pt}
**業務改善のご報告**

{align: center, block-width: 70%}
この文章は、本文領域の70%の幅のブロックに中央寄せで表示します。

{color: #c5221f}
この段落は全体を赤系の文字色にします。
```

配置は `left` / `center` / `right`。段落などの幅は `block-width`、表の各列幅は `widths`、画像の幅は画像直後の `width` と、指定場所が異なります。

### 4.5 引用・囲み枠・リンク・コード

```markdown
> 前回会議では、確認手順を一本化する方針が承認されました。

{box}
> 注意：提出前に、金額と承認者を必ず確認してください。

参考：[社内ポータル](https://example.com/portal)

保存するファイル名は `週次報告.md` です。
```

囲み枠は引用記号 `>` と組み合わせます。通常の引用と囲み枠を使い分けると、引用文と注意事項を区別できます。一般のHTMLタグで自由にレイアウトする機能はなく、`<br>` 以外のタグを装飾手段として使わないでください。

複数行のコマンド例や設定内容は、バッククォート3個で囲んだコードブロックにします。

````markdown
```text
文書フォルダ/
  報告書.md
  images/
    画面.png
```
````

コードブロック内では、通常の装飾記号やTyperの属性行を説明用の文字として書けます。

## 第5章 表で情報を整理する

### 5.1 列幅と列ごとの配置

```markdown
{widths: 20%, 55%, 25%}
{header-bg: #e8f0fe}
| 優先度 | 対応内容 | 期限 |
| :---: | :--- | ---: |
| 高 | 受付手順書を改訂する | 10月23日 |
| 中 | よくある質問を共有する | 10月30日 |
```

`Ctrl+Alt+T` で列幅付き表を挿入し、列名・割合・本文を変更すると手早く作れます。幅の個数は列数にそろえ、まず合計100%の割合指定を使ってください。PDFでは `30mm`、`1fr`、`auto` なども扱いますが、HTMLと共通に使うなら `%` が扱いやすく、`fr` はHTMLの列幅として同じようには働きません。

区切り行の `:---` は左寄せ、`:---:` は中央、`---:` は右寄せです。金額や数量は右寄せ、状態の短い語句は中央寄せにすると比較しやすくなります。

### 5.2 列幅と背景色は別の行に書く

`widths` は後ろのカンマ区切り全体を列幅一覧として扱います。`{widths: 20%, 80%, header-bg: ...}` のように混ぜず、前節の例のように別の属性行を並べます。複数の属性行は直後の表へまとめて適用されます。

### 5.3 セル内の改行・塗りつぶし

```markdown
{widths: 25%, 50%, 25%}
| 担当 | 作業内容 | 状態 |
| :--- | :--- | :---: |
| 山田 | 手順書を更新<br>承認後に共有 | [完了]{bg: #e6f4ea} |
| 佐藤 | 運用結果を集計 | [確認待ち]{bg: #fff2cc} |
```

セル内改行は `Shift+Enter`、または `<br>` を入力します。セル全体の内容を `[...]{bg: 色}` で囲むと、PDF/HTMLではセル全体の背景色になります。文章の一部だけを囲めば文字のハイライトになります。

表セル内の色文字には `[重要]{red}` を使います。旧式の `{color:red|重要}` は表の区切り記号 `|` と衝突しやすいため、表内では避けてください。セル結合には対応していません。

## 第6章 画像・目次・改ページで仕上げる

### 6.1 画像を入れる

1. まず原稿を保存し、画像と原稿の置き場所を決めます。
2. 挿入位置をクリックし、「画像...」または `Ctrl+Alt+I` から画像を選びます。画像のドロップでも挿入できます。
3. 必要なら画像の直後に `{width: 50%}` を追記します。
4. プレビューを確認し、原稿と画像をまとめて保管します。

```markdown
![申請フォームの入力例](images/form.png){width: 60%}
```

対応するローカルファイルの拡張子は PNG / JPG / JPEG / GIF / SVG / WebP です。個々の画像内容によって読み込みに失敗する場合があるため、出力前にも確認します。幅未指定は80%。画像の代替テキストはPDFで図のキャプションにも使用されます。

相対パスは保存済み原稿のあるフォルダを基準に解決されます。未保存原稿ではアプリの作業フォルダが基準になるため、先に保存してから画像を入れると場所の混乱を避けられます。「別名保存」で違うフォルダへ移すときは、画像も移すかパスを修正してください。

Web上の画像URLをダウンロードしてPDFへ取り込む機能はありません。ファイルを用意して挿入します。見つからない画像はプレビュー/PDFで「画像未検出」の枠になるため、PDF出力が成功した場合でも画像の存在を確認してください。画像の左右配置や文字の回り込みには対応していません。

### 6.2 目次とアウトライン

```markdown
# 運用手順書

:::toc

## 1. 作業前の確認

確認事項を書きます。

## 2. 実施手順

手順を書きます。
```

「目次」ボタンは `:::toc` を挿入します。見出しを変更すると、目次も再生成されます。PDFではページ番号付き、HTMLでは見出しへのリンクになります。Wordではフィールド更新が必要です。

`Ctrl+Shift+O` のアウトラインは執筆中の移動用です。原稿へ目次を挿入する操作とは別です。どちらも通常の見出しを基準にするため、中央寄せの太字段落だけでは項目になりません。

### 6.3 ページを区切る・余白を入れる

```markdown
ここまでが概要です。

:::pagebreak

## 詳細資料

:::space 2em

確認者：________________
```

改ページは `Ctrl+Enter`、明示的な空白は `Ctrl+Shift+Enter` でも挿入できます。空白の既定は `1em` で、必要なら `2em` や `10mm` に変更します。PDFのページ区切りとブラウザ上の連続表示は一致しません。

### 6.4 上級者向け：Typstで数式や図形を書く

「Typstコード」挿入ボタンは、実行する組版コードのひな形を原稿へ入れます。ツールバーの「Typstコード」チェックボックスは、生成されたコードを見るための表示切り替えです。

````markdown
```typst
#line(length: 60%, stroke: 1pt)
$ (a + b) / 2 $
```
````

このブロックはPDFとプレビューで実行されます。HTMLでは注記とソース、Wordでは省略の注記になります。通常の本文に `$...$` を書くだけでは数式になりません。また、外部Typstファイルの読み込みやパッケージ利用を前提にせず、ブロック内で完結する記述を使ってください。

## 第7章 検索・置換と効率的な編集

### 7.1 文書中の用語を統一する

例：「担当部署」を「所管部署」に統一する場合。

1. `Ctrl+H` または `Ctrl+F` で検索・置換バーを開きます。両方とも同じバーの表示切り替えです。
2. 検索欄に「担当部署」を入力し、一致件数を確認します。
3. 「前へ」「次へ」で、置き換えてよい箇所か確認します。
4. 置換欄に「所管部署」を入れ、一箇所なら「置換」、すべてなら「すべて置換」を押します。
5. 意図しない結果なら `Ctrl+Z` で戻し、`Esc` でバーを閉じます。

「Aa」をチェックすると、大文字・小文字を区別しない検索になります。検索は原稿の文字列が対象です。本文だけでなく、画像パス、URL、設定欄、コード例にも一致するため、一括置換前には対象を確認してください。正規表現検索や文書をまたいだ検索は実装されていません。

### 7.2 書式挿入を安全に使う

太字・斜体・下線・文字色は選択範囲を囲みます。表・右寄せ段落・中央タイトル・幅指定・行間指定・囲み枠・テンプレートなどは、カーソル位置にサンプル構文を挿入します。選択があると挿入内容で置き換わるので、文章を残す場合は選択を解除してから操作します。

段落の幅や行間のボタンは属性行を挿入するものです。挿入後、その直後に適用したい本文を書きます。設定の前後で段落がつながらないよう、例のように空行を入れてください。

### 7.3 Undo / Redo の範囲

`Ctrl+Z` / `Ctrl+Y` は本文編集、書式挿入、一括置換、ページ設定の変更を戻す・やり直す操作です。履歴はタブごとに分かれています。ファイルの読み込み直しや新規作成では履歴がリセットされるため、別ファイルへ移る前に保存してください。既に出力・保存した外部ファイルの内容がUndoで巻き戻るわけではありません。

## 第9章 PDF・HTML・Wordに出力する

### 9.1 提出形式を選ぶ

| 形式 | 主な用途 | 操作 |
| :--- | :--- | :--- |
| `.md` | 後からTyperで編集する原稿 | 保存 / `Ctrl+S` |
| PDF | 紙面の体裁を固定して提出・印刷 | PDF出力 / `Ctrl+P` |
| HTML | ブラウザで連続して読む | HTML出力 / `Ctrl+Shift+E` |
| Word `.docx` | Wordで本文を編集してもらう | Word出力ボタン。専用ショートカットなし |

現在エディタにある内容を出力するため、未保存の変更も出力対象です。出力だけでは原稿を保存しません。出力成功後はステータスバーの「開く」から確認できます。

### 9.2 形式ごとの対応差

| 内容 | PDF | HTML | Word |
| :--- | :--- | :--- | :--- |
| 見出し・段落・単純なリスト・表 | 組版して出力 | ブラウザ表示 | 基本文字・表として出力 |
| 表の列幅 | 反映 | CSSの列幅として反映。百分率推奨 | 指定幅は反映されない |
| 表ヘッダー背景 | 反映 | 反映 | 反映 |
| 文字色・下線・太字等 | 反映 | 反映 | 基本的な文字装飾に対応 |
| 文字ハイライト・セル塗り | 反映 | 反映 | 反映されない |
| 段落の配置・幅・行間・サイズ属性 | 反映 | CSSとして反映 | 同じ組版にはならず、ブロック属性は反映されない |
| ローカル画像 | 埋め込み | 読み込めた画像をBase64で内包 | `[画像: 説明]` の文字に置換 |
| 通常のリンク | リンクとして出力 | リンクとして出力 | 青色・下線の文字。クリックできるリンクにはならない |
| 囲み枠 | 反映 | 反映 | 同じ罫線枠を再現しない |
| 目次 | ページ番号付き | 見出しへのリンク | Wordでフィールド更新が必要。生成フィールドはレベル1～3を対象 |
| 改ページ | 紙面を区切る | PDFと同じ紙面にはならない | ページ区切りとして出力 |
| 明示的な空白 | 指定した高さ | 指定した高さ | 固定の空きに置換。指定高を厳密に再現しない |
| ヘッダー・フッター・ページ番号 | 設定を反映 | ヘッダー・フッターは先頭・末尾に一度 | これらの設定は出力されない |
| 生Typstコード | 実行する | 注記とコードを表示 | 省略の注記のみ |

Wordは再編集用の簡易出力です。基本文字サイズ・行間・アクセントなどの全体設定も、PDFと同等には反映されません。体裁の確認用にはPDFを併せて用意します。Wordの目次は、Word側で目次を選択して右クリックの「フィールド更新」などを実行します。

HTMLはCSSと読み込めたローカル画像を一つのファイルに含めます。通常のリンク先の内容まで内包するわけではありません。PDFとHTMLでの読みやすさを両立したい場合は、極端な固定幅や生Typstを避けます。

### 9.3 提出直前の確認

1. 原稿を保存し、対象月・日付・担当者・金額を見直す。
2. 出力したファイルを開き、全ページの表・画像・改ページを確認する。
3. PDFを修正したくなったら原稿を編集し、保存と出力をやり直す。
4. 後日の編集用に `.md` と参照画像も保管する。

### 10.5 通常のエディタ操作とボタン専用機能

エディタにフォーカスがあるとき、`Ctrl+A` は全選択、`Ctrl+C` / `Ctrl+X` / `Ctrl+V` はコピー／切り取り／貼り付けに使います。これらはエディタ部品による標準操作で、上のアプリ独自キー一覧とは区別しています。

Word出力、目次挿入、内蔵テンプレート選択、生Typstひな形挿入、HEX色適用、最近使ったファイル、出力後に開く操作には、専用のアプリショートカットは割り当てられていません。対応するボタンやメニューを使ってください。検索の前後移動も「前へ」「次へ」ボタンを使い、F3などの専用キーは想定しません。

## 第11章 保存・バックアップ・復旧

### 11.1 原稿と付属画像を保管する

文書はUTF-8のテキストとして保存・読み込みされます。通常は拡張子 `.md` を使います。`.txt` も開けますが、PDF・Wordを読み込んで原稿へ戻す機能はありません。文字コードが異なる古いテキストは、UTF-8へ変換してから開きます。

保存フォルダの例：

```text
月次報告_2026年10月/
  月次報告.md
  月次報告.pdf
  images/
    実績グラフ.png
```

原稿の画像指定を `images/実績グラフ.png` にしておけば、フォルダごと移動しやすくなります。HTMLやPDFを渡すだけの場合と、編集用原稿を渡す場合を分けて考えます。

### 11.2 自動保存の実際の動作

自動保存は通常の保存とは別のバックアップです。現在の実装は、**アクティブな文書に未保存の変更があり、前回の自動保存時刻から30秒以上経過しているとき**に書き出します。「最後の入力から30秒待つ」動作ではありません。バックグラウンドのタブは対象外です。

| 原稿の状態 | バックアップ先 |
| :--- | :--- |
| `C:\Documents\報告書.md` を編集中 | `C:\Documents\報告書.autosave.md` |
| 保存先のない新規文書 | `%APPDATA%\Typer\untitled_autosave.md` |

名前のない文書は共通のバックアップ名を使うため、複数タブそれぞれのバックアップを残せるわけではありません。また、バックアップ書き込み失敗は画面に通知されない実装です。作業の区切りでは `Ctrl+S` を使い、別のタブへ移る前にも保存してください。

### 11.3 バックアップから戻す

1. エクスプローラーで、原稿と同じフォルダの `*.autosave.md` を探します。未保存文書なら、アドレス欄に `%APPDATA%\Typer` を入力します。
2. 元原稿とバックアップの更新日時を確認します。
3. Typerの新規タブでバックアップを開き、内容を確認します。
4. 「別名保存」で `報告書_復旧.md` などの別名に保存します。
5. 元原稿と比べ、必要な内容を採用します。

起動時にバックアップを自動で復元する機能ではありません。バックアップが常に原稿より新しいとも限らないため、内容を確認してから復旧します。

### 11.4 終了前の保存と設定ファイル

未保存の印 `*` は、保存が必要な変更があることを示します。終了時には全タブの未保存状態が検査されますが、**確認ダイアログの「保存して続行」は全タブの一括保存ではありません**。現在のタブを保存して処理を進めるため、複数タブを編集していた場合は終了前に各タブを選んで保存してください。

| 設定ファイル | 内容 |
| :--- | :--- |
| `%APPDATA%\Typer\recent_files.txt` | 最近使ったファイル。最大8件 |
| `%APPDATA%\Typer\dark_mode.txt` | ライト／ダーク設定 |
| `%APPDATA%\Typer\untitled_autosave.md` | 名前のない文書用バックアップ |

最近使ったファイルの一覧はファイルへの参照です。元の文書を移動・削除すると開けなくなるため、「開く」から移動後の原稿を選択します。

## 第12章 困ったときの対処

| 症状 | 確認すること・対処 |
| :--- | :--- |
| 設定が反映されない | 設定を文書先頭の `---` 内へ置く。値の引用符や行末コメントを外す |
| 見出しが目次に入らない | `## 見出し` のように半角空白を入れる。太字や大きい文字だけの段落は見出しにならない |
| 改行されない | 空行で段落を分けるか、行末のバックスラッシュ／`<br>` を使う |
| 空行を増やしても余白が増えない | `:::space 1em` などを独立した行へ入れる |
| 表が崩れる | 区切り行と各行の列数を確認。セル内改行は `<br>`。装飾に旧式のパイプ記法を使っていないか確認 |
| 表の列幅がおかしい | 列数と幅の個数をそろえる。`widths` と他の属性は別行。まず合計100%の割合指定で試す |
| 画像が見つからない | 原稿の保存場所、相対パス、画像の実在・拡張子を確認。別名保存後は基準フォルダも確認 |
| PDFは成功したが画像がない | 「画像未検出」の枠がないか確認し、パスを直して再出力 |
| Wordがプレビューと違う | 第9章の対応表を確認。原稿を直す前に、PDFで同じ箇所が正しいか確認 |
| プレビューでエラーが出る | 最近変更した属性値や生Typstブロックを確認。直前の変更ならUndoして切り分ける |
| エラーの行番号が原稿と合わない | `[生成コード N行目]` は生成Typstの行番号。`Ctrl+Alt+Y` でコードを表示して確認 |
| 太字などが二重に入る | 書式ボタンは解除トグルではない。記号を削除するかUndo |
| PDFの修正が反映されていない | 原稿の保存だけでなく、PDFも再出力する |
| 絵文字が四角になる | UIとPDFで使うフォントが異なる。文書内は通常の文字表現へ置き換える |
| 名前のないタブが前回起動時の状態に戻らない | 全タブ復元機能はない。必要ならバックアップを手動で確認する |

現在の実装では、セル結合、画像への文字回り込み、上付き・下付き文字、ページ番号書式の自由変更には対応していません。表計算、自動承認、PDFからの編集原稿復元もありません。必要な表現が作れないときは、単純な表や段落へ整理するか、PDF専用の生Typstブロックを検討します。

## 第13章 構文早見表と実装の対応

### 13.1 よく使う構文

| 目的 | 記法・指定 |
| :--- | :--- |
| 見出し | `#`～`######` の後に半角空白と見出し |
| 太字 / 斜体 / 取り消し線 | `**太字**` / `*斜体*` / `~~取り消し~~` |
| 下線 | `[対象]{underline}` |
| 文字色・サイズ・背景 | `[対象]{color: #c5221f, size: 12pt, bg: #fff2cc}` |
| 単純な色指定 | `[対象]{red}`。blue / green / orange / purple / gray / black も使用可能 |
| 右寄せ | `{align: right}` を直前の独立行へ |
| 中央寄せ・サイズ | `{align: center, size: 16pt}` を直前へ |
| 段落の表示幅 | `{block-width: 60%}` を直前へ |
| 段落の行間 | `{line-height: 1.2}` を直前へ |
| ブロックの文字色 | `{color: #c5221f}` を直前へ |
| 表の列幅 | `{widths: 25%, 75%}` を表の直前へ |
| 表のヘッダー背景 | `{header-bg: #e8f0fe}` を表の直前へ |
| 囲み枠 | `{box}` の後に `> 注意文` |
| 画像の幅 | `![説明](images/photo.png){width: 50%}` |
| 段落内改行 | 行末に半角バックスラッシュ、または `<br>` |
| 改ページ | `:::pagebreak` |
| 余白 | `:::space 1em`。値省略時も1em |
| 目次 | `:::toc` |
| 横罫線 | 独立行の `---`。文書先頭では設定欄との混同に注意 |
| 生Typst | 言語名が `typst` のフェンスコードブロック |

### 13.2 実装上認識される別名

既存文書を読むための参考です。新しく書くときは本書で使っている通常のキーに統一すると管理しやすくなります。

| 対象 | 通常の記法 | 認識される別名 |
| :--- | :--- | :--- |
| 全体の文字サイズ | `font-size` | `fontsize` / `size` |
| 全体・ブロックの行間 | `line-height` | `lineheight` |
| 全体のフォント | `font` | `font-family` |
| 全体のアクセント | `accent-color` | `accent` |
| 全体のページ番号 | `page-number` | `page-numbering` / `numbering` |
| 表の列幅 | `widths` | `width`（画像幅・段落幅とは指定場所が異なる） |
| ブロック・インラインの文字色 | `color` | `c` |
| ブロック・インラインのサイズ | `size` | `font-size` |
| インラインの背景 | `bg` | `highlight` |
| インラインの下線 | `underline` | `u` / `下線` |
| インラインのサイズ短縮 | `[対象]{size: 12pt}` | `[対象]{12pt}` |
| 改ページ | `:::pagebreak` | `{pagebreak}` / `::: pagebreak` |
| 目次 | `:::toc` | `{toc}` / `::: toc` |
| 空白 | `:::space 1em` | `::: space 1em` |

インラインの旧式記法 `{color:red|対象}` も解析されますが、表内では `[対象]{red}` を使ってください。
